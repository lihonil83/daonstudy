# Phase 5 App Shell Smoke Tests

### 작업 이름

- 작업 ID: `phase5-app-shell-smoke-tests`
- 작업 제목: `Phase 5 앱 셸 스모크 테스트와 잘못된 경로 안내 추가`
- 상태: `done`
- 담당 범위: `App 라우트 셸, 공통 레이아웃, fallback 화면`

### 1. 목표

- 주요 페이지 테스트를 넘어, 앱 전체 진입 흐름이 공통 레이아웃과 함께 정상 렌더링되는지 자동으로 검증한다.
- 잘못된 경로에서도 사용자가 빈 화면 대신 다음 행동을 선택할 수 있도록 안내 화면을 제공한다.

### 2. 배경

- 개별 화면 렌더 계약 테스트는 충분히 넓어졌지만, `App -> Router -> Layout -> Outlet` 흐름 자체는 아직 자동 검증 범위 밖이었다.
- 현재 라우트 구조에는 `*` fallback이 없어 잘못된 경로에서 안내가 부족했다.

### 3. 영향 범위

- 수정 대상 파일: `src/App.jsx`, `src/components/Layout/**`, `src/pages/NotFound/**`, `tests/**`
- 영향 받는 문서: `docs/ops/work-units/**`
- 영향 받는 기능: 앱 진입, 공통 네비게이션, 잘못된 경로 안내

### 4. 비포함 범위

- 실제 클릭 기반 네비게이션 테스트
- 브라우저 히스토리 동작 테스트
- 외부 링크 또는 deep-link 수동 검증

### 5. 완료 기준

- `App` 라우트 구성이 테스트 가능한 셸 구조로 정리된다.
- 홈/과목/복습/기록 등 공통 레이아웃 기반 라우트 진입을 자동 검증할 수 있다.
- 잘못된 경로에서 fallback 화면이 렌더링된다.
- `npm run check`가 성공한다.

### 6. 검증 방법

- `npm run check`
- `appShellRender.test.js`

### 7. 선행 조건 / 의존성

- 필요한 문서 결정: 없음
- 필요한 파일/구조: `src/App.jsx`, `src/components/Layout/Layout.jsx`
- 사용자 확인 필요 여부: 없음

### 8. 리스크

- Router 추상화가 과도해지면 실제 런타임 구조와 테스트 구조가 괴리될 수 있다.
- 서버 렌더 기반 스모크 테스트는 실제 클릭 전환까지는 검증하지 못한다.

### 9. 작업 메모

- `AppShell`과 `AppRoutes`를 분리해 실제 앱 구조는 유지하면서도 `MemoryRouter` 기반 테스트가 가능하도록 만들었다.
- 개별 페이지 내부 구현 대신 라우트 연결만 보려는 목적에 맞게, 테스트에서는 각 페이지를 stub으로 대체했다.
- fallback 화면은 학습 흐름으로 빠르게 복귀할 수 있는 3개 링크를 제공한다.
- 레이아웃 상태 카드 문구도 현재 구현 수준에 맞게 갱신했다.

### 10. 인수인계 조건

- 라우트 셸 테스트가 5회 수정 후에도 안정화되지 않으면 `docs/ops/HANDOVER.md`에 실패 경로, 사용한 router 설정, 서버 렌더 로그를 함께 기록한다.
