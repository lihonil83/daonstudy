# Phase 5 Render Contract Tests

### 작업 이름

- 작업 ID: `phase5-render-contract-tests`
- 작업 제목: `Phase 5 JSX 렌더 계약 테스트 추가`
- 상태: `done`
- 담당 범위: `시각 카드/단원 화면 서버 렌더 테스트`

### 1. 목표

- 브라우저 테스트 라이브러리가 없는 환경에서도 JSX 컴포넌트가 핵심 정보를 제대로 렌더링하는지 자동으로 검증한다.

### 2. 배경

- 퀴즈 엔진과 단원 수가 크게 늘면서 모델 테스트만으로는 UI 계약 일부를 놓칠 수 있다.
- 현재 저장소에는 `jsdom`이나 Testing Library가 없으므로, 이미 설치된 도구 범위 안에서 서버 렌더 기반 검증을 먼저 확보하는 것이 가장 효율적이다.

### 3. 영향 범위

- 수정 대상 파일: `tests/**`
- 영향 받는 문서: 없음
- 영향 받는 기능: 시각 카드 렌더링, 과목별 단원 목록 렌더링

### 4. 비포함 범위

- 실제 브라우저 클릭 상호작용 테스트
- 애니메이션 테스트
- localStorage 연동 UI 테스트

### 5. 완료 기준

- JSX 컴포넌트를 테스트에서 불러올 수 있는 로더가 준비된다.
- `QuestionVisual`의 핵심 시각 타입이 정적 마크업으로 검증된다.
- 수학/영어 단원 목록 페이지가 주요 단원 제목을 렌더링하는지 검증된다.
- `npm run check`가 성공한다.

### 6. 검증 방법

- `npm run check`
- `questionVisualRender.test.js`
- `pageRender.test.js`

### 7. 선행 조건 / 의존성

- 필요한 문서 결정: 없음
- 필요한 파일/구조: `src/components/Quiz/QuestionVisual.jsx`, `src/pages/Math/Math.jsx`, `src/pages/English/English.jsx`
- 사용자 확인 필요 여부: 없음

### 8. 리스크

- CSS module과 JSX를 테스트 환경으로 가져오는 과정이 번들링 도구 변화에 영향을 받을 수 있다.
- 서버 렌더 테스트는 상호작용까지 검증하지 못한다.

### 9. 작업 메모

- `esbuild`를 이용해 테스트에서 JSX 파일을 읽어오고, CSS module은 stub으로 대체했다.
- 훅에 의존하는 페이지도 검증할 수 있도록 모듈 스텁 기능을 로더에 추가했다.
- `Progress`, `Review` 페이지의 빈 상태와 기록 상태를 각각 렌더 계약으로 검증한다.
- `Home`의 보상/복습 요약과 `QuizSession` 결과 화면도 렌더 계약 테스트로 묶었다.
- 브라우저 상호작용 테스트가 가능한 환경이 생기면 이 테스트는 더 높은 단계의 테스트를 보완하는 역할로 남길 수 있다.

### 10. 인수인계 조건

- JSX 로더나 서버 렌더 테스트가 5회 수정 후에도 안정화되지 않으면 `docs/ops/HANDOVER.md`에 실패한 번들링 단계와 재현 절차를 함께 기록한다.
