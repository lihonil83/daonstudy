# Phase 6 User-Ready Home And Progress

### 작업 이름

- 작업 ID: `phase6-user-ready-home-progress`
- 작업 제목: `Phase 6 사용자용 홈 추천 흐름과 기록 초기화 추가`
- 상태: `done`
- 담당 범위: `홈 추천 UX, 기록 초기화, 사용자 문구 정리, 테스트 보강`

### 1. 목표

- 개발자 중심 문구를 실제 사용자 기준 문구로 정리한다.
- 홈에서 다음에 무엇을 하면 되는지 바로 보이도록 추천 시작 흐름을 추가한다.
- 기록 페이지에서 학습 데이터를 안전하게 초기화할 수 있게 한다.

### 2. 배경

- 앱 기능은 이미 사용 가능한 수준이지만, 첫 실행 사용자가 다음 행동을 고르기 쉽게 안내하는 부분은 아직 약했다.
- 실사용 단계에서는 개발 단계 표현보다 학습 흐름과 기록 관리가 더 중요하다.

### 3. 영향 범위

- 수정 대상 파일: `src/pages/Home/**`, `src/pages/Progress/**`, `src/components/Layout/**`, `src/hooks/**`, `src/utils/**`, `src/models/**`, `tests/**`
- 영향 받는 문서: `docs/ops/work-units/**`
- 영향 받는 기능: 홈 진입 경험, 추천 시작 흐름, 학습 기록 초기화

### 4. 비포함 범위

- 배포 설정 추가
- 로그인/사용자 계정 도입
- 다중 프로필 지원

### 5. 완료 기준

- 홈 화면에서 현재 학습 상태에 맞는 추천 시작 링크가 보인다.
- 기록 페이지에서 학습 기록 초기화 동선이 제공된다.
- 개발 단계 문구가 사용자 중심 문구로 정리된다.
- 관련 렌더 테스트와 모델 테스트가 추가되고 `npm run check`가 통과한다.

### 6. 검증 방법

- `npm run test`
- `npm run check`
- `npm run smoke:browser`
- `npm run smoke:browser:prod`

### 7. 선행 조건 / 의존성

- 필요한 문서 결정: 없음
- 필요한 파일/구조: `src/pages/Home/Home.jsx`, `src/pages/Progress/Progress.jsx`, `src/utils/storage.js`
- 사용자 확인 필요 여부: 없음

### 8. 리스크

- 추천 시작 로직이 지나치게 복잡해지면 오히려 예측하기 어려워질 수 있다.
- 초기화 동선이 너무 쉽게 노출되면 실수로 데이터를 지울 수 있다.

### 9. 작업 메모

- 홈 추천 로직은 `homeModel`로 분리해 review 우선, 첫 시작 추천, 다음 단원 추천 순서로 계산한다.
- 기록 초기화는 storage key 상수를 중심으로 한 번에 비우고, 기존 구독 구조가 자동으로 화면을 다시 그리게 한다.
- Progress 화면에는 즉시 삭제 대신 한 번 더 확인하는 단계를 둔다.

### 10. 인수인계 조건

- 추천 시작 흐름 또는 기록 초기화가 5회 수정 후에도 안정화되지 않으면 `docs/ops/HANDOVER.md`에 실패 조건, storage key 상태, 화면별 오동작 문구를 함께 남긴다.
