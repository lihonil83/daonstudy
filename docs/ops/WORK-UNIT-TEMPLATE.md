# WORK-UNIT-TEMPLATE.md

이 문서는 개발 작업을 `작업 단위` 기준으로 정의할 때 사용하는 표준 템플릿이다.

목적:

- 큰 작업을 완료 가능한 단위로 쪼갠다.
- 각 작업의 완료 기준과 검증 방법을 미리 고정한다.
- 막혔을 때 `docs/ops/HANDOVER.md`로 자연스럽게 연결한다.

사용 원칙:

- 하나의 문서는 하나의 완료 기준 묶음만 다룬다.
- 헌법 변경, 문서 정합성 정리, 앱 기능 구현은 가능하면 별도 작업 단위로 나눈다.
- 완료 기준이 둘 이상으로 갈라지면 작업 단위를 분리한다.
- 검증 방법이 없으면 작업 단위를 시작하지 않는다.

## 빠른 체크리스트

- `목표`가 한 문장으로 말할 수 있는가?
- `영향 범위`가 파일/기능 기준으로 보이는가?
- `비포함 범위`가 있어 작업이 불어나지 않게 했는가?
- `완료 기준`이 검증 가능한 문장인가?
- `검증 방법`이 실제 명령 또는 확인 행동으로 적혀 있는가?
- 5회 재시도 후 넘겨야 하는 조건이 보이는가?

## 간단한 예시

### 작업 이름

- 작업 ID: `phase1-routing-shell`
- 작업 제목: `Phase 1 라우팅 뼈대 만들기`
- 상태: `planned`
- 담당 범위: `앱 초기 뼈대 + 라우팅`

### 1. 목표

- HashRouter 기반으로 5개 페이지가 이동되는 기본 앱 뼈대를 만든다.

### 2. 배경

- `PLANS.md`의 Phase 1과 `docs/exec-plans/active/mvp-plan.md`의 첫 단계에 해당한다.

### 3. 영향 범위

- 수정 대상 파일: `package.json`, `vite.config.js`, `src/App.jsx`, `src/main.jsx`
- 영향 받는 문서: `FRONTEND.md`, `ARCHITECTURE.md`
- 영향 받는 기능: 기본 페이지 이동

### 4. 비포함 범위

- 퀴즈 데이터 연결
- XP/진도/오답 저장
- 실제 문제 화면 구현

### 5. 완료 기준

- 홈/수학/영어/복습/진도 5개 경로가 렌더링된다.
- HashRouter로 정적 실행 시 페이지 이동이 가능하다.
- `vite.config.js`에 `base: './'`가 반영된다.

### 6. 검증 방법

- `npm run build`
- 브라우저에서 `dist/index.html` 열기
- 각 네비게이션 링크 클릭 확인

### 10. 인수인계 조건

- 빌드 실패 또는 정적 라우팅 실패가 5회 수정 시도 후에도 해결되지 않으면 `docs/ops/HANDOVER.md`에 기록한다.
