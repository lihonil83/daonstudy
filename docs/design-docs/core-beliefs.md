# Core Beliefs — 교육 원칙

## 이 문서의 목적

모든 기능 설계와 UI 결정의 기준이 되는 교육 원칙을 정의한다.
"이 기능을 이렇게 만들어도 될까?" 고민될 때 이 문서를 기준으로 판단한다.

---

## 대상

- 초등학교 2학년 남자아이 1명
- 게임처럼 노는 걸 좋아하고, 직접 풀어보면서 배우는 타입
- 학습 시간이나 분량에 제한을 두지 않음 (자기주도)

---

## 핵심 원칙

### 1. 놀이가 먼저, 학습은 자연스럽게

> "공부하러 가자"가 아니라 "게임하러 가자"가 되어야 한다.

- 퀴즈는 게임 미션처럼 느껴져야 한다
- 정답을 맞히면 즉각적인 보상(XP, 이펙트, 소리)이 있어야 한다
- 레벨업, 뱃지, 연속 학습 보상 등으로 "한 판 더"를 유도한다
- 강제로 시키는 요소(일일 할당량, 타이머 압박)는 넣지 않는다

### 2. 틀려도 괜찮다 — 힌트로 다시 도전

> 오답은 벌이 아니라 배움의 기회다.

- 틀리면 바로 X 표시 대신, **힌트를 주고 다시 풀 기회**를 준다
- 힌트는 단계적으로 제공한다 (1차: 가벼운 힌트, 2차: 더 구체적인 힌트)
- 최종적으로 틀려도 정답을 알려주며 "다음엔 맞출 수 있어!" 톤 유지
- 오답 복습은 선택적으로 — 아이가 하고 싶을 때 한다
- 틀린 문제 수보다 **맞힌 문제 수를 강조**한다

### 3. 자기 속도로, 원하는 만큼

> 아이의 호기심과 컨디션을 존중한다.

- 일일 학습량 제한 없음 — 하고 싶으면 계속, 하기 싫으면 언제든 그만
- 단원 순서 강제하지 않음 — 하고 싶은 과목/단원 자유 선택
- "오늘 안 했어요" 같은 죄책감 유발 UI 금지
- 대신 "3일 연속 학습!" 같은 긍정적 연속 기록은 보여줌

### 4. 작은 성취를 크게 축하한다

> 동기부여의 핵심은 "나 잘하고 있구나"라는 느낌이다.

- 퀴즈 완료 시마다 결과 화면에서 축하 메시지
- 레벨업 순간에 특별한 축하 화면 (애니메이션/이펙트)
- 뱃지는 노력 기반 — 점수보다 **도전 자체**를 보상
  - 예: "첫 퀴즈 완료", "오답 복습 도전", "5일 연속 학습"
- 다른 아이와 비교하는 요소 없음 (혼자 쓰니까 자기 자신의 성장만 보여줌)

### 5. 단순하고 직관적인 화면

> 8살 아이가 설명 없이 바로 쓸 수 있어야 한다.

- 버튼은 크고, 텍스트는 최소화
- 아이콘과 색상으로 의미 전달 (읽기 부담 줄이기)
- 한 화면에 하나의 행동만 요구 (선택지 과부하 방지)
- 네비게이션은 2단계 이내 (홈 → 퀴즈, 홈 → 복습)

## 설계 체크리스트

새 기능을 추가할 때 아래 질문으로 검증한다.

| # | 질문 | 기대 답변 |
|---|------|-----------|
| 1 | 아이가 이걸 "게임"이라고 느낄까? | Yes |
| 2 | 틀렸을 때 아이가 위축될까? | No |
| 3 | 강제로 시키는 느낌이 있나? | No |
| 4 | 설명 없이 바로 쓸 수 있나? | Yes |
| 5 | 작은 성취라도 축하해주나? | Yes |

## 톤 & 보이스

앱 내 모든 텍스트는 이 톤을 따른다.

- **칭찬은 구체적으로**: "잘했어!" → "와, 7단을 다 맞혔어! 대단해!"
- **격려는 따뜻하게**: "틀렸습니다" → "아깝다! 힌트를 줄게, 다시 해볼까?"
- **존중하는 말투**: 반말이지만 무시하는 톤 금지
- **이모지 적극 활용**: 🎉 ⭐ 💪 🏆 등으로 감정 전달
